# 今天的實作：一個工具查多個影城分館

本版延續 bot-01 的電影查詢與確認票根流程，新增多分館能力。

## ADK 概念

同一個 agent 可以使用分館清單、單館場次與多館比較工具。先理解品牌和分館，再決定查哪個來源；不需要為每間電影院建立一個 agent。

## 今天完成的流程

1. 問「目前台北有哪些威秀分館可以查場次？」→ `list_cinemas`。
2. 問「比較信義威秀和西門威秀今天六點後《片名》的場次」→ `cinema_compare`。
3. 接著查西門明天 → `cinema_schedule`。

程式負責分館識別、日期驗證、版本分離與時間篩選；模型負責選工具與理解上下文。場次本身以程式格式輸出，來源資料不能被模型任意改寫成另一個時間。

## 實際遇到的問題

威秀官方頁面在瀏覽工具可見，但程式直接讀取收到 HTTP 403。改用開眼電影網公開的分館時刻表，清楚揭露第三方來源與資料限制，再附官方入口。不能把瀏覽工具看到資料就當成程式串接已成功。

## 驗證證據

見 [verification.md](verification.md)。手機 LINE 的新功能收發仍待實測；CLI 模型測試與手機實測分開記錄。

之後可再擴充分館，或接回個人想看片單與場次的交集。先驗證各資料來源，再決定擴充範圍。

## 延伸：擴充至全台威秀

依官方據點目錄核對 20 間威秀與 2 間 MUVIE，再逐館讀取第三方時刻表，22 間全部核對分館及日期成功。加入縣市篩選、MUVIE 篩選，以及同名分館候選清單。43 項回歸測試通過，真實模型已驗證跨城市查詢；現有 LINE 服務已更新並通過 webhook 200 驗證。詳見 [分館覆蓋表](vieshow-coverage.md)。

## 延伸：跨品牌全台清單

擴充到開眼目錄的 108 個據點。資料量增加後，除了多個品牌，還需要清單分頁、縣市判別，以及「有資料入口」和「能解析場次」的區別。102 個可解析場次，6 個僅圖片入口；50 項測試與真實模型流程通過。詳見 [全台覆蓋](taiwan-coverage.md)。
